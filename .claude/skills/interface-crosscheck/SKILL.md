# Interface Crosscheck — dingdong

유닛 테스트가 통과하는데 화면이 비어 있는 버그는 대부분 **경계면**에서 난다. 양쪽은 각자 옳고, 둘이 안 맞을 뿐이다. 검증의 핵심은 "파일이 있다"가 아니라 **"양쪽을 동시에 읽고 shape을 대조한다"**이다.

## 대조 대상 4종

### 1. 서버 함수 ↔ 호출부

- `createServerFn().validator(schema)`의 입력 스키마와, 호출부가 실제로 넘기는 객체의 키를 나란히 놓고 본다.
- 서버 함수의 **반환 객체 키**와 화면이 읽는 프로퍼티 이름을 대조한다. `data.items` vs `data.list` 같은 불일치는 타입이 `any`로 새는 지점에서 조용히 통과한다.
- `null`/빈 배열을 돌려줄 수 있는 경로가 있으면, 화면에 그 분기 처리가 있는지 확인한다.

### 2. Drizzle 스키마 ↔ 쿼리 ↔ 화면

- `src/db/schema.ts`의 컬럼명·nullable 여부 → `select({...})`에 실린 필드 → 컴포넌트가 렌더링하는 필드, 이 셋을 한 줄씩 맞춘다.
- 스키마를 바꿨다면 `drizzle/` 아래 마이그레이션 파일이 실제로 생성됐는지, `_journal.json`에 등록됐는지 확인한다. 스키마만 고치고 마이그레이션을 안 돌리면 로컬은 되고 배포는 깨진다.
- nullable 컬럼을 non-null로 읽는 코드는 실데이터가 쌓인 뒤에야 터진다. 타입이 아니라 **데이터 관점**으로 본다.

### 3. 서버 전용 모듈의 클라이언트 누출

- `*.server.ts`, `process.env.*`, `node:*` import가 클라이언트에서 로드되는 경로(라우트 컴포넌트, 훅, `src/components/**`)에 섞이지 않았는지 확인한다.
- 서버 함수 파일(`*.functions.ts`)은 클라이언트에서 import되지만, 그 안의 **핸들러 본문**만 서버에서 돈다. 모듈 최상단에 서버 전용 import를 두면 클라이언트 번들로 끌려간다 — 그래서 이 저장소는 핸들러 안에서 `await import("@/db")`를 쓴다.

### 4. 라우트 ↔ 사이드바/네비게이션

- 새 라우트를 추가했으면 `src/components/app-sidebar.tsx` 등 진입점에 링크가 연결됐는지 확인한다. 라우트만 만들고 링크를 안 붙이면 "만들었는데 안 보인다"가 된다.
- `routeTree.gen.ts`는 생성 파일이다. 손으로 고치지 않는다.

## 실행 순서

1. 변경된 파일 목록을 뽑는다 (`git status`, `git diff --name-only`).
2. 각 파일에 대해 위 4종 중 해당하는 경계면을 고른다.
3. **양쪽 파일을 함께 읽고** 표로 대조한다:

   | 경계면          | A쪽 (정의)              | B쪽 (사용)         | 일치 |
   | --------------- | ----------------------- | ------------------ | ---- |
   | getLessons 반환 | `{ lessons: Lesson[] }` | `data.lessons.map` | ✅   |

4. 불일치는 재현 경로와 함께 기록한다 — "이 화면에서 이 동작을 하면 이 값이 undefined".

## 점진적으로 돌린다

전체 완성 후 1회가 아니라 **모듈 하나가 끝날 때마다** 돌린다. 경계면 버그는 늦게 잡을수록 후보 구간이 넓어지고, 원인 후보가 넓어지면 추측으로 고치게 된다.
