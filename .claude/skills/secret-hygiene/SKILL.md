# Secret Hygiene — dingdong

이 저장소의 모든 비밀값은 **환경변수 단일 경로**로만 들어온다. 예외를 하나 만들면 그 예외가 커밋된다.

## 불변 규칙

1. **소스에 키 리터럴을 쓰지 않는다.** 테스트·주석·스크립트·마이그레이션 SQL 어디에도. 예시가 필요하면 `"sk-example-not-a-real-key"`처럼 명백한 더미를 쓴다.
2. **`.env`는 절대 커밋하지 않는다.** `.gitignore`가 `.env`와 `.env.*`를 막고 `.env.example`만 통과시킨다. 이 규칙을 우회하는 `git add -f`는 금지다.
3. **서버 비밀값은 클라이언트로 새지 않는다.** `process.env.X`를 읽는 코드는 `*.server.ts` 또는 서버 함수 핸들러 안에만 존재한다. `VITE_` 접두사 변수는 브라우저 번들에 그대로 박히므로, 비밀값에 이 접두사를 붙이지 않는다.
4. **키 값을 로그에 찍지 않는다.** 디버깅이 필요하면 존재 여부(`Boolean(key)`)나 마지막 4자리 힌트만 남긴다.
5. **키를 서버 함수 반환값에 담지 않는다.** 사용자 개인 키는 `hint`(마스킹된 조각)만 UI로 내보낸다 — `src/lib/user-api-keys.functions.ts` 참고.

## 새 키를 추가하는 절차

새 외부 서비스를 붙일 때는 **네 곳을 함께** 고친다. 하나라도 빠지면 배포 후 런타임에 터진다.

1. `src/lib/env.server.ts` — `ENV_SPEC`에 항목 추가 (required 여부, 어떤 기능이 꺼지는지)
2. `.env.example` — 주석과 함께 빈 값으로 추가 (팀·미래의 자신을 위한 문서)
3. `.env` — 로컬 실제 값 (커밋되지 않음)
4. Railway 대시보드 — 프로덕션 값

그리고 소비 지점에서 키 부재를 **사용자가 이해할 수 있는 한국어 에러**로 처리한다:

```ts
const key = process.env.PEXELS_API_KEY;
if (!key) throw new Error("영상 소스를 가져올 수 없어요 — PEXELS_API_KEY가 설정되지 않았습니다.");
```

## 사용자 개인 키(BYOK)

사용자가 자기 API 키를 넣는 경로는 다음 불변식을 지킨다:

- 저장 전 `src/lib/secret-box.server.ts`의 `seal()`로 AES-256-GCM 암호화한다. 평문 저장 금지.
- 복호화(`open()`)는 서버에서만, 그리고 곧바로 provider 팩토리에 넘긴다. **평문 키가 서버 함수 반환 경계를 넘지 않는다.**
- `open()`이 `null`을 돌려주는 것은 정상 실패 경로다(시크릿 로테이션·행 손상). 공용 키로 폴백하고 사용자에게 재입력을 안내한다.
- 데이터 키는 `BETTER_AUTH_SECRET`에서 HKDF로 파생된다. 이 값을 바꾸면 기존 저장 키가 전부 못 열린다 — 로테이션 시 사용자 재입력 안내가 필요하다.

## 점검 방법

변경 전후로 다음을 확인한다:

```bash
git ls-files | grep -E "^\.env$"        # 결과가 있으면 즉시 조치
```

소스에 키가 섞였는지 훑을 때는 제공자별 접두사 패턴(`AIza`, `sk-`, `eyJhbGciOi`)과 `Bearer ` 뒤 긴 문자열을 함께 본다. 실제 키가 커밋된 것이 발견되면 파일 수정만으로 끝내지 말고 **해당 키를 제공자 콘솔에서 즉시 폐기·재발급**한다. git 이력에 남은 값은 파일을 고쳐도 살아 있다.
