# A-1-18. 웹앱 Dingdong의 초기 뼈대 생성

> 논문 부록 A-1 · 개발 프롬프트(표준화) · 웹앱 Dingdong

**목적** : 화면의 뼈대와 이용자 인증의 초안을 얻는다. 자료 구조와 생성 기능은 다음 단계로 미룬다.

### 전제

① 빈 상태에서 시작한다.  
② 자연어로 화면과 기능을 만들고 배포까지 연결하는 도구를 쓴다.  
③ 데이터베이스와 인증, 파일 보관, 서버 함수를 함께 제공하는 관리형 백엔드 서비스를 쓴다.  
④ 생성 모델의 키를 서버 쪽에만 등록할 수 있다.

### 프롬프트

```text
[목표어]를 배우는 [학습자] 대상의 학습 플랫폼을 만든다.
지금은 전체가 아니라 토대만 만든다. 한 번에 다 만들지 않는다.

기술 조건
- 화면은 [프런트엔드 프레임워크]와 유틸리티 기반 CSS, 공용 컴포넌트 모음으로
  구성한다.
- 데이터베이스와 인증, 파일 보관, 서버 함수는 관리형 백엔드 서비스를 쓴다.
- 생성 모델의 호출은 모두 서버 함수에서 한다. 키는 서버 함수의 비밀값으로만
  보관하고 화면 쪽 코드에 노출하지 않는다.

이번 단계에서 할 것
① 디자인 체계를 정한다. 파스텔 색조, 반투명 카드, 둥근 모서리로 통일한다.
② 첫 화면, 강좌 목록, 강좌 상세, 강의 상세, 단어장의 다섯 경로를 빈 화면으로 둔다.
③ 상단 막대와 왼쪽 사이드바로 이루어진 화면 틀을 둔다.
④ 백엔드 서비스를 연결하고 로그인과 회원가입의 빈 화면을 둔다.

자료 구조와 생성 기능은 이 단계에서 만들지 않는다. 위의 넷만 한다.
```

### 비고

Lovable에 남아 있던 대화에서 원자료를 확보하여 실제 발화에 따라 다시 썼다. 이 프롬프트의 요점은 이번 단계의 범위를 넷으로 묶고 자료 구조와 생성 기능을 뒤로 미룬 것이며, 같은 형태의 범위 제한이 이후의 요청에도 되풀이된다. 자료 구조와 생성 지시문은 이어지는 요청에서 주어졌고, 그 지시문은 플러그인에서 쓰던 것을 옮긴 것이다. [A-1-19](A-1-19.md)가 이 단계의 산출물을 전제로 한다.
